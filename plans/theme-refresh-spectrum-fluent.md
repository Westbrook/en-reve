# Spectrum 2 and Fluent source refresh — 2026-09-20 UTC

**Status:** Spectrum evidence below remains current. The current API already supported the richer baseline values; the former generator's unconditional `createReviewDraft({})` prevented these candidates from using them.

## Spectrum changes

- **Correct desktop M typography.** UI/input moves from 16/20 to **14/18**, with body remaining **16/24**. The previous UI metric represented S2's larger size. `page.css` sets a 14px base; `style/spectrum-theme.ts` maps `ui` to font-size-100 and rounds line height. Metadata now follows detail M at **14/18, weight 500**. The three host heading roles map to Spectrum headings S/M/L at **20/24, 22/26 and 28/32, weight 800**. Shared strong labels use weight 700. This uses exact code-authored ratios, not rounded managed choices. [Typography implementation](https://github.com/adobe/react-spectrum/blob/4dd44e0f400636a87a9ad4390903e78c5ae6113c/packages/%40react-spectrum/s2/style/spectrum-theme.ts), [page defaults](https://github.com/adobe/react-spectrum/blob/4dd44e0f400636a87a9ad4390903e78c5ae6113c/packages/%40react-spectrum/s2/page.css).

- **Use three-layer elevation.** `shadow.overlay` maps to `drop-shadow-elevated`: `(y, blur, alpha)` is **(4,12,.08), (2,6,.04), (0,2,.12)** in light, and **(4,12,.24), (2,6,.12), (0,2,.36)** in dark. Toast follows the same elevation. The dialog shadow becomes transparent because the inspected S2 Modal has no shadow. ## Recommendations for the first official theme API

Fluent-specific examples in this section came from React component implementation files. They are secondary product evidence, not observations of the Fluent 2 website skin. The [current findings](theme-refresh-fluent2-api-findings.md) revise that distinction, add navigation/current-state separation and consumed-role provenance, and preserve the website CSS/elevation-article disagreement.

1. **Ship a supported trusted-baseline transport.** This refresh demonstrates that the compiler already handles custom fonts, 800 weight, exact ratios, alpha and shadow arrays. The former candidate pipeline exposed less capability than the API. Keep the new per-branch baseline route with strict identity validation, managed preservation and exact reopen tests; distinguish baseline literals, managed choices and CSS-only customization in documentation.
2. **Add focused family geometry/state contracts where evidence repeats.** Spectrum needs field-only 2px borders and focused border paint; Fluent needs neutral top/side strokes plus independently accessible bottom strokes. One shared boundary or border width cannot encode either accurately. Token chips need border width and hover/pressed foreground roles. Do not solve these through global control pins.
3. **Support variant-scoped recipes without losing state or export fidelity.** Existing button state hooks are useful CSS APIs, but an unscoped override applies to primary, secondary, ghost and danger together. Fluent secondary buttons use white/neutral rest and gray hover/press, while the host secondary semantic fallbacks differ. A serializable optional variant recipe, or an officially supported companion stylesheet with declared scope/reset behavior, would close this gap without adding arbitrary global palettes.
4. **Separate family motion profiles.** Spectrum Popover uses200ms/4px; Modal uses250ms entry,130ms exit,20px entry travel and160ms delay. Current shared popup/modal timing cannot match both. Prefer explicit family recipes with reduced-motion policy and stable geometry guarantees; state/focus should remain immediate.
5. **Treat typography as metrics plus environment.** Exact medium typography is expressible; size-dependent rounded line heights, distinct title versus heading roles, locale-specific fonts/weights and coarse-pointer typography are not. Spectrum switches base14→17 and scale1→1.25 on coarse pointers. Add carefully bounded typography/environment recipes and explicit font asset provisioning rather than assuming a declared family is installed.
6. **Expand rendered diagnostic contexts.** Compiler checks cover six declared pairs, not toast semantic fills, links over selected/subtle surfaces, chip interaction states, decorative icons or outline surroundings. This pass independently checks those pairings. A family/state background matrix should accompany theme publication, with alpha compositing and actual inherited backgrounds distinguished from opaque token arithmetic.
7. **Track source disagreement and deliberate departures.** Retain separate design-data and component-runtime versions, immutable links, source role names and fidelity/adaptation labels. Native picker behavior, choice-control brand roles, asymmetric toast spacing, font loading, icon geometry and interaction anatomy remain distinct from color matching. One inspiration label cannot certify all of them.
