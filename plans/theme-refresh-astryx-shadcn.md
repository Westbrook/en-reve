# Astryx and shadcn reference audit — 2026-09-20

The refreshed recipes preserve the **branded Astryx website skin** and **shadcn homepage Rhea / Neutral** identities. Neither is replaced by a generic component-library default. Official current source was read, pinned, and compared with the previous mappings. This is a source-backed interpretation on En Rêve components, not an official theme or a pixel-equivalence claim.

Astryx was inspected at official commit [`413fa55281d1565abae8319e9803c8ccc639bc28`](https://github.com/facebook/astryx/tree/413fa55281d1565abae8319e9803c8ccc639bc28), dated 2026-09-20 00:54 UTC. ## How the latest APIs are used

Previously the recipes started from `createReviewDraft({})`. That unnecessarily limited the theme to the generic editor's stock fonts, dimension choices, motion increments, and shadow presets. The current source API already supports exact font stacks, arbitrary typed dimensions, precise durations, translucent colors, and structured shadow arrays. The refresh therefore supplies an authoritative per-mode `ThemeOptions.source` baseline, then replays the remaining managed edits. No core API is added.

The per-mode baseline fragment is [theme-refresh-astryx-shadcn-base.json](theme-refresh-astryx-shadcn-base.json); the catalogue integrates it into each theme definition. Historical managed approximations are removed where they would override the precise source baseline. Existing registered CSS hooks such as `--en-table-header-background`, `--en-skeleton-color`, and `--en-progress-track-color` receive typed source tokens. Each has a real stylesheet consumer. Application-owned viewport, data, selection, and controller configuration is not made part of the visual theme.

## Remaining API recommendations

1. **Make source baseline plus managed edits a first-class documented authoring path.** These improvements needed no new token capabilities, but the old generic-baseline workflow hid existing power. Imported baselines must remain authoritative and build-bound. Distinguish restore-to-themed-baseline from restore-to-library-default.
2. **Keep component state and variant refinement independent.** Generic button hover/background pins affect primary, secondary, ghost, and danger together. They cannot express Rhea's subtle destructive fill or independent secondary hover without erasing other variants. Add narrowly typed per-variant roles or a documented scoped composition recipe with state precedence tests.
3. **Separate choice and switch visual geometry/paint.** Astryx checkboxes are20/24px independently of16px icons. Its switch thumb grows14→16px or16→20px when checked; our one thumb dimension cannot capture that. Off-track/unchecked-thumb paint also needs dedicated family roles. Avoid changing a global icon size to solve a checkbox detail.
4. **Add family typography where source hierarchy demands it.** Editor tokens inherit ordinary UI typography, preventing exact12px/20px/500 chips independently of14px controls. Dialog title, card title, and metadata also need independent semantics if exact hierarchy is a v1 goal. Keep responsive input16px on small screens separate from desktop14px, with protected zoom/readability behavior.
5. **Expose surface distinctions where they materially differ.** Generic overlay paint is shared across dialogs, popovers, and tooltips. Astryx uses different dark dialog/popover colors and inverted tooltips; Rhea distinguishes card shadow-sm, popup shadow-lg, and dialog shadow-xl. Popup/dialog shadows now map, but there is no card elevation hook. Source backdrop blur and input inset state shadows also remain unexpressed.
6. **Improve semantic contrast receipts.** Compiler checks ordinary text/action pairs but missed the preexisting Astryx success badge failure. Include status text against actual contextual/translucent badge surfaces, plus several ancestors. Preserve distinction between a color chosen for fill/icon and one chosen for ordinary text. Current light danger corrections and stronger muted text remain explicit local adaptations.
7. **Provide per-family motion without encoding behavior in theme data.** Source toast and popup curves/timings differ, as do button press scale(.98 Astryx) and translation(1px Rhea). These button movements are not implemented by the current inspired recipes: existing timing tokens do not supply a press-transform consumer. The [pressed-state follow-up](theme-refresh-pressed-states.md) confirms Astryx omits shrink inside ButtonGroup and zeroes duration, but retains scale, under reduced motion. Rhea omits its shift on controls carrying `aria-haspopup`. Support bounded visual slots and portable scoped recipes with explicit reduced-motion policy; keep focus, dismissal, queue admission, and state transitions immediate and behavioral.
8. **Expand compound/alpha-aware managed editors rather than introducing duplicate capabilities.** Shadows already accept multiple layers in source; source alpha already works on fields and borders. The editor should expose and preserve those structures with context-aware contrast. Offer explicit font asset manifests/loading status, since a font-family string alone does not establish actual rendering.
9. **Document viewport versus content sizing and axis-specific insets.** A384px source toast viewport is not necessarily a384px toast once En Rêve region padding is applied. Astryx selector list inset is4px block/5px inline, while one scalar popup padding cannot encode it. Prefer clear role units and separate axes over more near-matching presets.

These are recommendations for the API review, not claims of implemented core behavior. Unsupported visual details remain disclosed; stateful controls, focus protection, forced colors, coarse-pointer floors, and reduced motion retain the reusable system's behavior.

## Verification

[Verification receipt](theme-refresh-astryx-shadcn-verification.json) records all four final branches: managed replay over their exact source baselines, zero compiler diagnostics, emitted CSS, and byte-identical export/reopen/export. Declared ordinary text/status-badge contrast was checked over canvas, surface, and raised surface, with alpha composed against each ancestor; toast text was checked against its plate. Minimum measured ratios: Astryx light4.526:1, Astryx dark6.586:1, shadcn light4.539:1, shadcn dark5.240:1. This is focused mathematical evidence, not a complete accessibility certification or visual acceptance. Integrated browser review belongs to the parent refresh checkpoint.
