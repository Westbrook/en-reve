## P0: Move fast failure detection before expensive preparation

**Evidence.** `run-comprehensive.mjs:101-107` executes every selected producer before any ordinary check. This means all docs, framework, packing, registry, reader, candidate preparation precedes consumer types even where dependencies are just tokens/primitives/elements/SSR. Checks/types/Python then run serially at :121-126. The graph defaults most direct checks to `build` (`comprehensive.mjs:78`), and **95 of 150 Node tasks carry the full `build` dependency**. A previously registered dependency is retained rather than tightened by discovery (`comprehensive.mjs:40,50`). `build` entails docs (`pathways.mjs:12-26`). This is conservative scheduling, not a dependency-optimal order.

**Historical measured confirmation.** Existing passing warm run `artifacts/test-runtime-2026-09-25/final-warm-correctness-current-v3/execution.json` (Sep26 source/runtime cohort) records consumer-types 0.413s starting 127.921s after invocation; primitives-types 0.201s at128.384s; breadcrumbs-types0.052s at128.634s; styles-check0.210s at128.736s; scoped consumer0.069s at128.995s. This is direct evidence for the requested earlier negative markers. It is not a current timing estimate.

**Plan.** Declare each gate's exact prerequisite artifacts, reads/writes, failure class, and resource class; distinguish source-only checks from built consumer checks. Keep explicit stale-artifact checks before any producer that could repair them (existing API preflight :96-100 is precedent; AGENTS requirement is broader). Define a fail-fast preflight path and a single owned validation plan that schedules each cheap check immediately when its smallest true prerequisites exist. Run source checks first; check tokens/styles/primitives/elements/SSR consumers as their products become ready; defer docs rendering, framework setup, packing, candidate prep until prerequisite cheap checks succeed. Update public views without broadening their documented prerequisite/argument boundaries.

**Do not add duplicate work.** Package build `tsc` already validates production: tokens/package.json:59, styles:188, primitives:29, elements:44, SSR:28. Docs has a typecheck inside build after npm prebuild (`apps/docs/package.json:7-11`). Split or expose this existing failure stage when useful instead of unconditionally appending a duplicate blanket noEmit compile. Styles `check` re-runs authoring+tsc after styles build (`styles/package.json:188-189`); investigate whether an equivalent successful build satisfies that precise obligation. Keep authored-CSS freshness semantics.

**Acceptance.** Seed syntax/type/stale-metadata failures and show no unrelated browser server/docs/candidate/framework producer starts; record time-to-first-actionable-failure and CPU spent before failure. Compare cold and warm stable snapshots. Verify produced artifacts and complete assertion/engine/profile coverage remain identical. A single early sentinel command must not become another required pass appended before unchanged full duplicate work.

## P1: Resource-aware execution instead of unconditional phase serialization

**Evidence.** Producer loop serial (:101-107); check loop serial (:123); all browser discovery serial (:135-147); all browser configs serial (:214); custom/browser-owning commands deferred to end (:216-223). Graph topology is used for ordering but no readiness scheduler consumes it. Independent build primitives and tokens are already separate dependency roots (`pathways.mjs:12-13`), yet are serialized. Hardcoded three-worker caps are in multiple layers (`run-comprehensive.mjs:40,125,139`; `public-views.mjs:81`; `bounded.mjs:3`), not a shared resource token allocator.

**Plan.** After true artifact edges are declared, add one scheduler within the existing machine/checkout lease. Give each task CPU/browser slots, exclusive write roots/ports, fixture/service affinity, and performance exclusivity. Ready cheap checks outrank slow preparation; independent producers can share unused capacity; browser tasks stay within a total CPU/browser/RSS budget and preserve lower per-config maxima. Keep Node's useful single invocation for a cohort of ready source files, splitting only when prerequisite/failure latency warrants it. Never run two 3-worker subprocesses thinking the total is3. Group or co-locate compatible tasks around one prepared fixture/service without merging isolated test state. Retain fails-closed dependency handling and `--continue-independent` semantics.

**Acceptance.** Trace demonstrates no conflicting output writers/ports, total budget respected, all owned children drained on failure/interruption, no timed campaign overlap, same outcomes/facets. Benchmark resource budgets1/2/3 and only then optional higher machine profiles; choose best wall time/RSS/reliability, not highest worker count. Compare negative latency as well as passing throughput. Start with independent producer/check cohorts before attempting cross-config browser concurrency.
