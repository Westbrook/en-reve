# Documentation and skills initial pass

The user requested documentation and skill development while continued platform
and manual testing is stalled. This work starts from local main `3485f568` and
leaves the previous source/evidence history intact.

## Delivered scope

| Area | Delivery | Boundary |
| --- | --- | --- |
| Application users | Handbook with task routes, input conventions, failure/recovery and preference guidance | Owning live demos supply exact keyboard behavior; manual usability and translated documentation are not certified |
| Developers | Registration, CSS delivery, authored/data ownership, synchronous/asynchronous state recipes, labels, frameworks, SSR and verification routing | Installed public declarations are authoritative; application callbacks and services remain application-owned |
| Designers | Group/component/concept scopes, full/partial behavior, derived values, appearance, sizes, property registration and candidate review | No automatic adoption, remote submission authority or contrast certification |
| Agents | Matching CEM/receipt/type/API artifact index with hashes and seven portable skills for component authoring, functional testing, accessibility testing, documenting, consuming, building apps and theming | No personal installation, new CLI/MCP service or invented universal event payload |
| Maintainers | Source authoring, freshness-before-regeneration, proportionate validation, migration and release-draft guidance | No version bump, package release or visual-baseline promotion |
| Discovery | Handbook links from sticker sheet, showcase, workflows and repository README | Existing examples and reference pages retain their current URLs |

Authored content lives in `apps/docs/guides.html`; `guides.ts` only preserves the
existing trusted Progress Report link convention. Portable skills live in
`skills/`; documentation preparation copies their exact bytes and hashes them
alongside the actual published metadata. The generated index contains no build
timestamp, private report paths or copied mutable task state. Changes to skills
invalidate documentation preparation through its existing content inventory.

## Completion criteria

- Accurate public contract examples, linked owning guides and explicit limits.
- Guide accessible without JavaScript; narrow layout avoids page overflow;
  keyboard navigation, fragments and report return behavior work.
- Distributed skills match authored bytes, pass skill validation, and route
  realistic consumer/theme tasks to the public contracts used by the examples.
- Metadata digests match the complete published sibling set.
- Fresh production build and focused browser checks; exact source/build published
  to GitHub main, gh-pages (including the requested base tag), and the existing Site.

## Skill responsibility review

The seven skills each declare one primary output and explicit adjacent owners.
`skills/catalog.json` is the distribution inventory; `skills/README.md` maps
realistic requests to their primary skill. Consumption addresses one existing
component; app building owns routing/service/workflow composition; component
authoring owns library implementation. Functional tests and accessibility
acceptance have distinct evidence boundaries. Documentation and theme authoring
do not implicitly trigger runtime changes or a release. References are contract
lookups, not automatic invocation of another entire skill workflow.
