# Fluent 2 website: API findings

Reviewed September 20, 2026. The refreshed inspiration targets the actual [Fluent 2 website](https://fluent2.microsoft.design/); its published foundations and component guidance fill roles that the site does not demonstrate. This is a focused API/provenance supplement, not a replacement recipe or a claim of pixel equivalence.

## Separate the skin from its underlying system

Use three evidence classes: **observed website styling**, **published product guidance**, and **our adaptation**. Record the winning computed value, selector, appearance and viewport for the first class. A token declaration alone does not prove the website consumes it.

This distinction matters here. The captured [site stylesheet](https://fluent2websitecdn.azureedge.net/cdn/accessibility.C8FxN6HQ.css) contains the standard 14px/20px product ramp and 4px medium radius alongside documentation h1 at 68px/92px with −.04em tracking, root fluid sizing, and a separate site palette. The [homepage stylesheet](https://fluent2websitecdn.azureedge.net/cdn/index.Brk4meEG.css) adds Arbutus accents, 22px tile corners, 24px image panels, animated gradient borders and backdrop blur. These declarations are evidence of available treatments; page-specific overrides and actual computed consumers determine the refreshed mapping. Source URLs, hashes and bytes are retained in `artifacts/fluent2-refresh/source/manifest.json`.

Do not preserve a generic blue, 14px-body, 4px-control theme merely because those values occur in the underlying Fluent token table. Conversely, decorative homepage illustration assets and navigation layout are not new component-theme requirements.

## Claims to revise in the previous Fluent report

- **Baseline identity:** the prior claim that the existing blue palette, 14/20 UI/body and 4px corners remain the correct inspiration is insufficient for the website target. Keep component-guidance values only where the actual website and chosen role support them.
- **Elevation agreement:** the site's CSS `--shadow64` retains light .12/.14 and dark .24/.28 layers. The [elevation article](https://fluent2.microsoft.design/elevation) instead publishes high-ramp light .24/.20 and dark .28/.20 equations with different ambient blur. Its low-ramp text also repeats some equations. Preserve this disagreement; do not silently label package numbers as a literal transcription of the article or replace measured website CSS with prose equations.
- **Exact focus, toast and chip claims:** prior option offset, animated field accent, toast icon colors and InteractionTag metrics were traced to React implementation files. They can supplement unrepresented roles, but are not observations of the website's branded skin.
- **Universal platform claims:** Fluent publishes distinct web, Windows, macOS, iOS and Android ramps. Do not combine their dimensions or treat a native-platform convention as mandatory for this web inspiration.

## Release recommendations

Prioritize (1) provenance at the consumed-role level, (2) independent navigation/current and bounded family state recipes, (3) card elevation, typography tracking and a versioned CSS/asset companion, and (4) rendered state/context validation. The trusted per-appearance baseline transport is already delivered; it is no longer a proposed capability.

[Button guidance](https://fluent2.microsoft.design/components/web/react/core/button/usage) requires text 4.5:1 and icons 3:1 in interactive states. The [accessibility guidance](https://fluent2.microsoft.design/accessibility) also calls for visible focus, 200% text enlargement and reflow at 400%/320px. These are verification obligations for the adaptation, not certifications inherited from its source. Keep native picker differences, responsive application composition and manual assistive-technology review explicit.

## Linked Web Components cross-check

The user-supplied [Combobox Storybook](https://storybooks.fluentui.dev/web-components/?path=/docs/components-combobox--docs) was inspected in Web Light and Web Dark. Its combobox is a `fluent-dropdown type="combobox"`, with paint on the internal control, not the host. The immediate outer contour, inner contrasting contour and bottom accent coexist. This corrects the earlier React-only characterization of that combination as a departure. The [audit](theme-refresh-fluent2-web-components.md) also distinguishes checkmark selection from keyboard-active borders and records the pinned source version separately from the unknown deployed version.

These findings strengthen proposals for independent input edge/state paints and label/helper typography, bounded family motion, and stable Parts with documented reachability through slots and nested shadow roots. The website’s larger corners, editorial type and rose selection remain the visual authority; product-default blue/4px styling is not silently substituted.
