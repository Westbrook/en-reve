# TREE-2 / TREE-3 implementation contract

The user authorized both slices after accepting tree multi-selection and upload improvements.

- Lazy data branches: `lazy` marks unknown children; `branch` marks a folder even when empty. Property-only `loadChildren({key,item,requestId,signal})` returns children. The element commits validated results atomically. Collapse, disconnect, loader replacement and explicit `items` writes abort pending work. Ignored aborts cannot revive stale results. Concurrent completions preserve each other. Retry is explicit after failure. Known selection/expansion keys are retained. Fetching, application error details, auth and caching remain application-owned.
- The finite and virtual data renderers share this model. Authored children retain app-owned DOM loading; a `branch` marker represents an empty folder and allows expansion while the app supplies nodes. No implicit conversion of rich slotted content into plain data.
- Opt-in `reorderable` adds a dedicated pointer/touch handle and an external keyboard/touch Move interface. Alt+M opens Move for the focused row/selection. Destination and before/after/inside controls use the same pure proposal helper as dragging. No deprecated ARIA drag attributes.
- `moveItems(keys,target,position)` dispatches a cancelable `en-reorder` proposal before committing. Applications may veto or replace data/DOM themselves. Preserve selected keys, relative preorder, and focused moved key. Selected descendants travel with selected ancestors, never twice. Reject cycles, disabled sources/ancestors/destinations, unknown keys, no-ops and inside-unloaded targets. Inside a loaded empty folder is supported. This is a separate structural proposal, not a change to the existing selection `en-change` snapshot.
- Virtual drag targets are mounted rows. Edge scrolling reveals additional targets; the Move interface lists the complete known hierarchy. Moving into unknown remote children requires loading the folder first. A drag starts only on its handle to preserve normal scrolling and selection. Escape/pointercancel aborts. Touch uses pointer capture; equivalent controls remain available without dragging.
- Demos simulate loading, empty/error/retry/concurrent/canceled work; include code samples, authored reorder and virtual/full modes. Automated tests establish browser/SSR behavior, not physical-device or spoken-output acceptance.
