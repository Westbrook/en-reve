Use the controls

Try a complete task in the sign-in workflow, settings, chat, project selection or asset browser. These examples simulate services locally; they do not send messages, upload your files to a service or sign you into an account.

Move, select and act

Tab moves between controls or enters a composite. Arrow keys move within menus, tabs, trees and other composites according to their pattern. Space toggles checkboxes; Enter activates the focused action. Text fields retain their editing keys. Read the live example's keyboard help for its exact behavior.

For a multi-select tree, Shift-click selects the inclusive range from the anchor; Command-click on macOS or Control-click on Windows adds or toggles one item. Collapsing a group changes what is visible, not the application's stored data.

Recover without losing your work

Loading means a request is pending, not successful. Follow the local retry or cancel action after a failure. A failed chat message retains its content; sending a request does not itself erase the composer draft. Dialog dismissal and form submission are different actions.

Understand transient content

Tooltips provide supplementary help. Escape dismisses the active tooltip; a new hover can show it again without reviving the dismissed focus interaction. Essential instructions belong in visible content or a field description. Toasts report outcomes; use their local actions or history when supplied.

Build an application

1. Choose a pattern and its ownership

Use the searchable API reference for attributes, properties, events, slots, Parts and CSS properties; use the native recipes when ordinary HTML is sufficient. Keep routing, transport, persistence and business validation in your application.

Authored slots support rich application content. Data APIs support keyed collections, virtualization and application-owned rendering where documented. A table cell renderer returns cell content, not another td; activity and carousel renderers similarly receive component-owned wrappers. Use stable keys rather than array positions when items can move.

2. Register only what you use

Install matching private @en-reve packages through your approved package source or packed artifacts. No public npm availability is implied. With an ESM-capable bundler, this is a complete checkbox setup:

import '@en-reve/tokens/default.css';
import '@en-reve/elements/define/checkbox.js';

const field = document.createElement('en-checkbox');
field.name = 'includeSource';
field.value = 'yes';
field.label = 'Include source files';
document.querySelector('form').append(field);
field.addEventListener('en-change', event => {
  if (event.target !== field) return;
  if (!applicationAllowsSourceFiles()) event.preventDefault();
});

Supply your form and applicationAllowsSourceFiles() policy. For native ESM, provide JavaScript import maps and serve the exported token CSS at an ordinary stylesheet URL instead of importing CSS from JavaScript. Class-only imports, definitions and the main barrel do not register elements. Generated-child dependencies are included by the definition; authored children need their own registration.

3. Separate drafts, proposals and outcomes

A tentative change is synchronously cancelable: public state and form data already contain its proposal during dispatch. Call preventDefault() before awaiting an asynchronous decision. Authoritative property writes are silent and can supersede rollback. Guard stale responses so an older request cannot overwrite newer intent.

let revision = 0;
field.addEventListener('en-change', event => {
  if (event.target !== field) return;
  event.preventDefault();
  const request = ++revision;
  const proposed = event.detail.proposed;
  void savePreference(proposed).then(accepted => {
    if (request === revision) field.checked = accepted;
  }).catch(error => {
    if (request === revision) showSaveError(error);
  });
});

This is an alternative policy to the first handler. The application supplies savePreference and visible showSaveError feedback, and invalidates the revision on disposal or an authoritative external update. The example demonstrates checkbox state only; do not apply its payload to every event. en-action, editing notifications and load-response events have their own contracts.

4. Preserve semantics across delivery modes

Use the documented label/description API to name the real control. Named label slots avoid whitespace masking choice-label fallbacks. Keep help links in descriptions. External for references use the same document or shadow root. Do not add unsupported host ARIA forwarding or query private shadow markup.

Bind live editing through the component API without resetting the value on every render. Preserve composition, drafts, selection and pre-hydration edits. SSR must create request-local state with matching initial server/client snapshots. The existing scoped and lazy APIs distinguish loading from registration, construction, hydration and readiness.

5. Check the integration you actually ship

Start with the task's focused tests: keyboard and pointer operation, cancellation, delayed failure, reset and changing content. Match package and browser versions to the recorded evidence. The support ledger separates patched engines, retail browsers and manual/device coverage. Passing DOM snapshots do not certify spoken output.

Design and theme

Start with the showcase to see assembled interfaces, then use the sticker sheet for individual states. Color, type, rhythm, density and size interact; review content expansion and narrow layouts as well as a single attractive frame.

Choose the smallest customization boundary that expresses your intent
IntentUseEffect
Whole application themeToken resolver and full theme emissionRecomputes derived values and resets registered component pins at the new boundary.
Related controlsGroup properties such as --en-control-background or --en-input-backgroundChanges the documented family within its CSS scope; a more specific component pin can still win.
One component or regionOptional component property, such as --en-button-radiusInherits through that region until a full theme resets it or a closer override replaces it.

.compact-tools { --en-button-radius: 9999px; }
.compact-tools en-button { --en-button-background: var(--en-color-surface); }

Verify the chosen background with its foreground and hover/focus/pressed states. A raw accent seed change does not recalculate generated contrast colors. For coordinated changes, use resolveTheme() and emitted theme CSS. Full themes replace inherited pins; partial overrides preserve unspecified pins. A primitive changed on a descendant does not automatically recompute an inherited alias.

Theme boundaries and browser preferences

default.css provides system-responsive light/dark values and document-level property registrations. Named theme files loaded afterward establish independent full scopes. With custom emission, load properties.css once or emit registrations explicitly. Optional override registrations preserve fallback behavior; giving every custom property a concrete initial value would mask parts of that chain.

Component size defaults to medium; size="inherit" is explicit. Density changes rhythm independently. An overlay rendered outside the intended region needs the corresponding theme at its actual inheritance boundary. Retain focus contours, contrast, reduced-motion behavior and touch targets; hover-only paint is gated by @media (hover: hover).

Prepare a reviewable candidate

  1. Open Theme Review, choose a single or paired context and make the smallest useful edit.
  2. Inspect direct, derived and pinned values. Compare the candidate against its exact base on the full sheet and relevant workflows.
  3. Export the candidate. Reopening checks the matching docs build and regenerates recorded edits; it does not execute imported CSS.
  4. Record interaction, visual and manual results separately. A rendered preview is not a passed test.
  5. Apply an explicitly accepted candidate to authoritative source, regenerate outputs and run the affected checks. Exporting or reviewing does not adopt it automatically.

Work with an agent

Retrieve contracts before producing code. The installed package is authoritative for your application; this hosted page describes its own build. The machine-readable contract index records the SHA-256 identity of each delivered artifact and skill. Digests establish file identity, not compatibility or behavioral acceptance.

  1. Find a pattern in the API reference or inspect the whole Custom Elements Manifest.
  2. Retrieve the matching public API graph, type snapshot, and generation receipt. Do not mix builds.
  3. Use a complete example from the selected pattern; retain explicit registration and its application-owned callbacks.
  4. Compile against the installed public declarations and exercise the actual consumer behavior. The metadata-to-consumer pathway demonstrates this for a bounded checkbox scenario.

Portable skills

Each skill owns one responsibility. Choose the skill that matches the requested outcome; a component integration does not automatically trigger application architecture, theme design or a full release workflow. Combine skills only when the task crosses those boundaries.

Download a skill, inspect it, and place it in the named folder supported by your agent with the filename SKILL.md. The files are usable independently; installing one does not modify your application or authorize publishing.

  • en-reve-component / SKILL.md — write components, shared layers and public delivery contracts.
  • en-reve-test / SKILL.md — functional state transitions, consumer integration and reproducible evidence.
  • en-reve-accessibility / SKILL.md — semantics, keyboard/focus, automated checks and honest manual acceptance.
  • en-reve-document / SKILL.md — executable examples, generated contracts and audience-specific guidance.
  • en-reve-app / SKILL.md — assemble workflows, service adapters, state and responsive interfaces.
  • en-reve-consume / SKILL.md — discovery, imports, state ownership, forms, collections and delivery.
  • en-reve-theme / SKILL.md — coordinated tokens, scopes, Parts, CSS authoring and candidate review.

Example request: “Use en-reve-consume to add an export checkbox to this form, preserving our asynchronous save policy.” For theming: “Use en-reve-theme to give only the inspector's buttons pill corners while retaining the fields' defaults.” These skills route to current contracts instead of carrying a duplicate component catalog. They are not installed into your personal environment by the docs build.

Contribute and release

Change the source contract once

Read the repository's contribution contracts and the owning component guide. Change definitions, implementation and authored docs together. For covered styles, edit packages/styles/src/css/ and regenerate. For tokens, change inputs and generators. Do not patch emitted CSS, metadata or historical receipts.

Run freshness checks against existing metadata before regeneration; otherwise regeneration can conceal a stale artifact. Then use the documented metadata commands to produce CEM, public types, API graph and sibling receipts together. Explicit registration, pure imports and generated-child dependencies remain part of the public contract.

Choose proportional verification

Use the pinned toolchain wrapper and a fresh EN_EXECUTION_OUTPUT directory. Start with the cheapest relevant semantic and pure checks, then the affected production-browser consumer. test:plan and test:inventory describe coverage; test:union executes the selected correctness pathways. Follow the pipeline guide for leases and reproducible run identity.

Inspect change impact

Each documentation build includes a source-backed impact manifest linking token aliases and fallbacks to CSS property readers, imported modules, components, authored examples and workflows. The impact tooling guide explains how to query a changed token or source file and inspect why each case was selected.

Open Theme Review to see affected components and cases for the current candidate, including both appearances of a pair. Choose a case to open it with the candidate applied; exports retain the source-impact identity. Missing or mismatched maps are reported as unavailable. This is potential impact: shared modules and assets intentionally select broadly. Unknown inputs expand to the full inventory. The complete review sheet remains required; selection is not a visual pass, a cache hit or an accessibility result.

Compare old and new versions

The interactive release review packager pairs two exact documentation builds with their release draft and authored scenario mappings. Full documentation versions run on independent local origins so controls, styles and storage stay separate. Exact authored component bundles can also coexist in two native scoped registries within the same document; unsupported engines report that path as not run, with no global fallback.

Select a scenario, load both versions, and compare their behavior beside change notes, migration guidance and API facts. Before/After layouts support smaller screens. Export observations tied to both build identities and reopen them only in that exact review. Added or removed surfaces have explicit unavailable reasons. A preview or observation does not approve or publish a release.

Explain a change and its migration

Capture exact base and candidate CEM/type artifacts; add authored notes for behavior and CSS changes that CEM cannot infer. The release-draft tooling proposes a version train and retains unknown classification. A draft does not publish packages or adopt a baseline.

  • Consumers migrating old controlled/request-change flows should use synchronous cancelable proposals and silent authoritative writes.
  • Use current authored navigation anchors rather than the removed element items API; keep routing and aria-current application-owned.
  • Use explicit define entries rather than relying on side effects from class or catalog imports.
  • Theme migrations must check full-theme resets, partial preservation and actual state paint; changing CSS names alone is insufficient.

Read the pending API migration notes and theme migration notes against your actual base version. Source links in this guide follow mutable GitHub main; freeze a commit when recording a release decision.

Delivery and known gaps

The implemented components, live examples, package contracts, scoped candidate tools and these guides are available for review. The consumer evidence audit records bounded coverage for 111 reusable public entries, 48 gallery copies and 11 complete API modules. It does not certify every possible composition.

Retail Safari input delivery, missing prior-browser/OS combinations, physical devices, manual assistive technology, IME and linguistic review remain separate obligations. Automated tree snapshots are not VoiceOver acceptance. Existing reported VoiceOver/virtual-list behavior remains a known manual follow-up, not a proven screen-reader bug.

Theme Review supports local edit/export/reopen. Offline candidate review packaging is available through the maintainer tooling above. Interactive old/new release review is also available as a portable package. A managed submission service and adoption authority remain separate. Their product choices remain in the experience plan. The historical external CSS-authoring rerun was retired by the user, not marked passed.

These guides are an initial documentation pass. Library-owned message catalogs do not mean all documentation prose is translated. Package publication, manual acceptance and review acknowledgment are distinct from a working site.
