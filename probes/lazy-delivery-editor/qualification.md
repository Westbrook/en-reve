# Packed contextual toolbar qualification

This separate fixture uses real packed rich-text editor and toolbar classes.
It supplements the route census and docs interaction suite; it does not measure
performance or establish route adoption.

The producer refuses an existing output directory and retains archive integrity,
actual ProseMirror input modules and output asset hashes. Public TypeScript
consumption is checked from extracted archives. No workspace alias may provide
an `@en-reve` module. The separate browser configuration owns port 4262 through
`EN_LAZY_DELIVERY_EDITOR_PORT`; the pipeline supplies
`EN_LAZY_DELIVERY_EDITOR_OUT` inside its fresh execution directory.

After the candidate and owning pipeline mapping are integrated, run the complete
fixture through its supported named pathway with a fresh outer directory:

```sh
EN_EXECUTION_OUTPUT=/absolute/new-editor-run tooling/test-pipeline/with-toolchain.sh npm run test:union -- --pathways=lazy-delivery-editor
```

The CSR matrix covers requested auto/global modes and ordinary, shadow and nested
roots. Two real editor/toolbar pairs share one registry so first selection must
construct only the selected instance's generated controls. Real Bold/Undo and
Link actions test bookmarks, cancelable changes, stale revisions, draft retention,
readonly/disabled/composition guards, disconnect/reconnect and retargeting. An
iframe owns an independently loaded real editor for adoption and stale-focus
coverage. Actual registry mode is recorded; Firefox fallback is ordinary engine
behavior, not capability mocking.

SSR pages compare eager and on-demand toolbars with an editor-only baseline.
The essential rich editor initially renders readable, readonly content and its
existing ProseMirror mount replaces that SSR editing node. The fixture records
this baseline limitation. Once the backend is live, separately hydrating or
constructing a toolbar must preserve the live editing node, editor host/shadow,
focus and selected text. The preselected on-demand cell qualifies the case where
an initially empty SSR toolbar becomes eligible before its first client render.

Composition events here are synthetic guard checks. Physical IME, actual screen
reader speech, touch selection, saved-profile restoration and autofill remain
separate manual acceptance. UI assertions are not a timing or retained-memory
campaign.
