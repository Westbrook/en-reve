# Packed pagination qualification

This separate correctness fixture consumes the real public pagination definition,
element-scope API and scoped SSR/hydration API from extracted package archives.
It supplements the docs interaction suite and candidate census. Pagination only
defers construction of its native chooser body; there is no optional module
loading or generated custom-element registration claim.

The producer rejects an existing output directory, validates packed public types,
rejects workspace library inputs, and records package archive integrity/SHA-256,
bundle inputs and output asset hashes. Its server defaults to port 4263, overridable
through `EN_LAZY_DELIVERY_PAGINATION_PORT`. The pipeline supplies
`EN_LAZY_DELIVERY_PAGINATION_OUT` within the fresh outer execution directory.

After the candidate and owning pipeline mapping are integrated, run through the
supported named pathway with a new, non-existing output path:

```sh
EN_EXECUTION_OUTPUT=/absolute/new-pagination-run tooling/test-pipeline/with-toolchain.sh npm run test:union -- --pathways=lazy-delivery-pagination
```

The source matrix has 29 CSR and 21 SSR cases per engine: 150 cases across the
pinned Chromium, Firefox and WebKit projects. This is the expected source count,
not an executed result. All known-total fixtures start with 12 pages.

CSR covers requested auto/global registration in ordinary, shadow, nested and
shared sibling roots; first click/Enter/Space/direct-native opening; default and
late eager policies; cancelable page transactions, drafts and native validity;
disabled/count boundaries; disconnect/reconnect; and both cold and used adoption
into another real document. First construction preserves the native shell,
numbered/current-page controls, shadow slots and their authored assignments.
Adoption asserts destination focus and one retained chooser, with the sibling
remaining unconstructed. Native opening is never replaced with a simulated event.

Each engine records actual scope capability and chosen registry. An engine's
ordinary auto fallback, including Firefox when its probe fails, is actual engine
evidence. A separate labeled test makes the scoped-registry constructor throw to
qualify forced auto fallback through the real global registry. This injected
capability failure does not establish native scoped-registry support.

SSR covers matching eager/on-demand snapshots; eager input identity and a dirty
native draft through client opt-in; pre-upgrade eager policy over the empty
server branch; native opening before and after hydration; and essential semantic
markup without JavaScript. A plain application-owned link establishes usable
no-JavaScript navigation. The component chooser remains CSS-hidden without its
JavaScript positioning, matching the established eager behavior; those checks
do not claim usable no-JavaScript pagination actions.

The native number input has no text-selection API contract. The fixture asserts
its value, node identity and focus, not a fabricated text range. Actual screen
reader speech, physical devices and browser profile restoration remain separate
manual acceptance. These checks do not establish timing, retained-memory savings,
route adoption, or the candidate's numeric promotion gates.


## Human review companion

Use a newly qualified immutable packed output at its own diagnostic origin. Existing routes `/ssr-global-eager.html?human-review&progress-report` and `/ssr-global-on-demand.html?human-review&progress-report` show **Asset pages**, initially page 3 of 12. The corresponding `ssr-shadow-…` pages exercise the existing shadow-island fixture. Record requested and actual registry mode. The opt-in native **Release pagination hydration** control is outside the hydration root and calls the existing `ssrPaginationFixture.hydrate()` once. No second component fixture or timer is added; the Progress Report link follows the existing local convention.

Present separately: (1) keyboard-open **Choose a page** while hydration is held; (2) use the native next-control key to reach **Release pagination hydration** and press Enter (Tab, or Option+Tab in macOS Safari when Tab omits buttons). The completed native opening is still hidden before release. After release the same shell becomes populated and visible while focus remains on Release. The button remains mounted and focusable after release; repeated activation is a no-op. A pointer click outside can light-dismiss the native popover, so it is not an equivalent positive-recovery step. The portable regression records the actual navigation key and uses Alt+Tab for local macOS WebKit, matching the established pagination docs tests. It still requires `:popover-open` before keyboard release instead of forcing it open. If an engine dismisses during traversal, retain that diagnostic failure and do not claim that cell as manual open-shell evidence.

For a separate closed-intent card, press Escape before tabbing to Release; hydration must keep the chooser closed and omit its unused on-demand body. Eager recovery is a compatibility repair with a separate disposition if lazy construction is rejected. Automatic transfer to **Page number** when focus never left the invoker remains covered by the existing test-controlled release, not a new manual-speech claim.

This companion adds five portable source cases per engine. It is separate from production `/api-examples/pagination.html?progress-report`, whose real **Mobile example pages** starts at page 6 of 40. Do not conflate these values or routes. Actual speech and physical-device acceptance require their own observations; neither fixture establishes performance or promotion. New tests and preview remain unexecuted until validation records their receipts.
