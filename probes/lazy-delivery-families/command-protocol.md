# Command settings actual-route measurement contract

This adapter observes the production settings workflow at `/workflows/settings.html` with no query, hash, alternate catalog, or extra palette. The fixed initial catalog has Save settings, Restore saved opacity, Cancel save, and Review incoming change; the last two are disabled. Initial local and saved settings remain the actual 64% opacity, PNG, portrait, included-background snapshot. The source workload and numeric gates are frozen in `plans/lazy-delivery/family-designs.json` under `designs.command-palette-design`; this document defines acquisition observations and does not replace or relax those gates.

The build applies the arm policy before SSR and before client hydration at the original `en-command-palette#settings-command-palette` in `apps/docs/src/workflows/settings/template.ts`. Reference uses its existing eager default, candidate authors `content-rendering="on-demand"`, and rollback authors eager against the same candidate source. Registration stays owned by the real route. Its existing entry calls load without registration, then the first Search commands activation ensures the definition. A declaration in the global owner registry is not assumed merely because an SSR shadow root exists.

## Startup and action observations

`installCommandProbe({family: 'command', policy: arm.policy})` is a serializable, self-contained Playwright init script. It exposes `window.__enFamilyProbe` with `state`, `snapshot()`, `arm(action)`, `action`, `isClosed()`, `closedSettled()`, `close()`, and `lifecycleCycle(kind)`.

Startup waits for the actual `en-workflows-app` hydration and pending defined descendants to settle, loaded document fonts, the original closed native palette shell, enabled real trigger, the exact four-command property snapshot, and the authored policy. Unregistered or deliberately deferred hydration subtrees do not trigger speculative registration. Counts are captured before action, focus, or scrolling. Startup records both `actualRegistry` (`unregistered` when the tag is unknown) and `routeRegistry` (`global`), plus `hostRegistered` and `hostUpgraded`. The first usable endpoint must separately establish global registration and upgrade.

The external trigger is `#settings-command-trigger`; its actual native button is selected with Playwright's shadow-piercing locator `#settings-command-trigger button`. Keyboard input uses trusted Enter and starts its clock at the native Enter keydown. Pointer input uses a trusted mouse click, or touchscreen tap for the phone pointer cells, and starts its clock at the resulting click. The listener only records events whose composed path contains this exact trigger. No command executes during this campaign.

An action is ready only after all of these observations hold across two animation frames with stable dialog geometry:

- The original registered palette is open, its native dialog is open and modal, and the surface is visible and not inert.
- The actual search input has focus, is enabled and editable with an empty query, is hit-testable, and has correct expanded combobox/listbox ID relationships and visible search label.
- The current four rows have the exact actions, labels and disabled states. The Save settings row is the selected, enabled active descendant and is hit-testable within the listbox and viewport. The remaining rows are unselected.
- The polite search status exists and is empty, loading feedback has cleared, the external trigger reports expanded, and the dialog fits the visual viewport.
- Pending component updates have completed. The endpoint records actual registration, native modality, search focus, current catalog and ARIA checks separately.

The driver closes with a real Escape key before repeating the same trigger. It waits for `isClosed()` to confirm both host/native closure, collapsed search ARIA and reset native query. Generated subtree identity and native input identity must remain unchanged on repeat. The input present in eager SSR is observed through a weak reference before the first activation; when deferred content is absent, the first generated input establishes the weak reference.

Complete component and complete document counts include light DOM, shadow roots, elements, text and comment nodes, with styles reported separately. Generated counts cover the four conditional label, focus frame, listbox and search-status subtrees. The unconditional command wrapper, default slot and surrounding template markers belong to the complete component count, so deterministic absence is reported with explicit combobox/listbox/row/search-status counters rather than an assumed zero for every shell marker. Resources retain full URL, origin, path, H2 protocol, browser encoded/transferred bytes and response timings; the common harness binds them to packed receipts.

## Delivery controls and interpretation

The primary `cold` route retains its real route-entry load-only behavior and first activation registration. It is an actual route first-use result, not by itself the frozen same-code construction-only gate. Separate, explicitly labeled controls use the symmetric measurement bridge and the route's supported loader operations. The policy-control owner defines `same-code`, `prepared-0`, `prepared-50`, `prepared-200` and `unused`; each records actual loading, registration, lead, traffic, and unchanged focus/open state. The first trusted action also records the bridge status synchronously at its event boundary, so pending versus completed preparation is observed at actual activation. Prepared lead controls cover all seven browser configurations and both input actions; the unused control has action `none` because activation is absent. Only the same-code cell may satisfy the frozen same-code first-use thresholds. Preparation lead and unused-preparation requirements cannot disappear merely because the cold route passes.

`closedSettled()` supports the same-code control after explicit ensure: it observes public update completion plus stable closed counts/geometry and rejects opening or focus movement. It never ensures, opens, focuses, scrolls, or changes the authored policy. Source, workload, package, asset and runtime provenance remain common across matched controls. Secondary controls must not be pooled with the unchanged cold route, and no unique optional-code saving is implied by the construction policy.

## Retention and limits

Each arm uses five fresh browser contexts for each independently labeled lifecycle, with 100 cycles and the common 0/10/50/100 checkpoints. Retained-host cycles activate the actual native Search commands button, await the usable endpoint, and call the public synchronous hide operation. Every opening compares weak references for all generated subtree nodes, and every close checks native input identity. A failure increments `workload.inputIdentityFailures` and fails the sample; it is not reset by selecting a replacement run.

Disposed-host cycles first register through the real original trigger when needed and record `lifecycleBootstrap: true`. That one-time bootstrap materializes the original host and remains visible in the cycle-0 versus later counts. Each disposed cycle then creates one palette, assigns the exact current four commands and policy before connection, opens and closes through public show/hide, verifies input identity across close, and removes it in a `finally` block. It does not copy SSR markup, IDs, `for`, `open`, or deferred hydration flags. The observer retains no strong references to removed hosts or generated nodes. Disposed-host results are separate from retained-host results; cycle-10 to cycle-100 comparisons avoid treating initial materialization as a leak.

The retention driver must include `EN-COMMAND-PALETTE` among the named detached host diagnostics. Its post-GC DOM counters, connected census, reported detached trees, listeners and heap evidence remain distinct; unsupported detached diagnostics are not zero. Programmatic lifecycle operations establish repeatability and retention evidence, not trusted first-use latency. No automated endpoint claims screen-reader announcement or physical IME acceptance. Browser qualification and acquisition have not been run by this source-authoring lane.
