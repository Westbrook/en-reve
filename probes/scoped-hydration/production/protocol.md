# Phase 5 matched SSR production campaign

The exact sealed Phase 4 commit is exported, built and npm-packed with no Phase 5 runtime imports. The candidate overlays only the new SSR implementation, package exports/dependency and TypeScript configuration on that same commit. Vite consumes extracted package tarballs. Receipts hash every measured asset and package. Both render the same 50-command palette template twice into inert HTML templates with a useful native form outside the optional islands. Native scoping is selected by the existing behavioral capability probe; fallback uses the document registry. Definitions are imported without global side effects.

Policies: Phase 4 eager application-owned hydration; Phase 5 route-entry load-only preparation; Phase 5 cold explicit activation. This new workload tests SSR activation. Earlier settings workflow measurements remain a separate historical series; their absolute times are not paired with this campaign.

Thirty successful fresh-context samples per policy/configuration, block-randomized with seed 20260921. Configurations: Chromium/Firefox/WebKit desktop keyboard; Chromium 4x CPU, 150 ms network latency, 1.6 Mbps download/0.75 Mbps upload with keyboard and emulated mobile touch; and throttled unused visits. HTTP/2 gzip. Timing begins at the browser click handler; shell readiness is native controls ready, and navigation-to-focus is reported to expose startup shifts. Immediate input is sent once shell readiness becomes observable, without deliberate preparation lead. Device emulation is not physical-device evidence. No outlier removal. Errors invalidate a run and are retained; never fill missing values with zero.

Unused visits are observed 500 ms after shell readiness, and are reported as observed windows rather than fully settled network totals. Both dynamic module requests and live/inert DOM are counted. Long-task/layout-shift metrics are Chromium-only; unsupported engines return null. Successful runs assert no page errors, failed requests or failed focus restoration. Separate retention: five fresh-context Chromium desktop runs per policy, 100 mount/activate/open/close/dispose/remove cycles, double GC at 0/10/50/100. Module caches are expected to remain. The harness retains one shared detached source template in every policy for lifecycle remounts; active islands release their own source templates. Connected/inert DOM counts traverse the document, while heap/DOM retention includes detached storage. GC is used only in retention runs.

Server costs: >=30 warm process-global renders versus >=30 request-isolated worker roundtrips, same packed template/payload and SSR output. This measures incremental server isolation overhead; it excludes network and build time. Requests are serial, with bounded worker concurrency; no claim about peak service throughput. Functional incremental transport is qualified separately; renderer output is buffered.
