What to test

  1. Autofill before hydration: choose a saved contact/address from your browser in the native form, then independently in the managed form. Note whether suggestions appear and which fields fill. Select Hydrate now, then Check managed form values. Values should survive and the local form entries should match the visible fields.
  2. Autofill after hydration: open a fresh copy, select Hydrate now first, then use browser autofill in both forms. Check the managed form entries again. Typing or pasting tests editing, not actual autofill.
  3. History after hydration: hydrate, edit both forms with distinct memorable values, and select Navigate away. Use your browser’s Back command. Note the return diagnostic and whether each form restores. If this is a new document, wait for restoration, then hydrate and check the managed form entries again.
  4. History before hydration: open a fresh copy, edit both forms while dormant, navigate away and Back, then hydrate. Compare the values before and after hydration. This separates browser restoration from hydration preservation.

If no browser autofill is offered for the native reference, record “not offered” rather than a pass. If only the managed form lacks suggestions, report that difference. Record the browser/version, delivery, return diagnostic and any missing or changed fields.

How to interpret this fixture

Browser autocomplete suggestions and history restoration are distinct features. A Back return may resume the same document from the back/forward cache (BFCache), or create a new document and restore form state. Both are useful results; this fixture labels the path and does not force either.

The shadow delivery uses a scoped registry where supported, with global fallback otherwise. The global delivery is a separate control. Before upgrade, the managed inputs are editable but their custom-element hosts are not yet form-associated. The form-entry check is therefore meaningful after hydration. A browser may deliver managed-field history restoration when the element upgrades, so an initially empty field becoming your remembered draft is a restoration result, not data loss. Preservation compares the exact inputs, values, selection and focus immediately before and after hydration; it does not assert that actual autofill or history restoration occurred.
