# Phase 6 date-picker production protocol

Exact parent 2dc77b5773839f7afdd52ce0b4fc68a6af35d0f4 versus enumerated candidate
overlay. Packages are built in isolated exported checkouts, npm-packed, extracted
and consumed by Vite. One essential date field with an eagerly retained dialog,
button and icon dependency set; deterministic Gregorian value 2026-09-15 and today
2026-09-22. The construction-only candidate imports the full eager graph but omits
the initial calendar. Cold/intent/route candidates consume the lighter shell graph.
Native scoped and explicit global modes are recorded; unsupported scoped requests
are labeled global fallback. No absolute subtraction against prior command studies.

Primary observations: Chromium/Firefox/WebKit desktop keyboard, Chromium constrained
keyboard and emulated touch, Chromium constrained unused and abandoned intent.
Constrained settings: CPU4x, 150ms, 1.6Mbps download/750Kbps upload. HTTP2/gzip6,
immutable JS/no-cache HTML, service workers blocked, fresh browser and context per
cold sample. Warm study navigates the same context twice (new document, HTTP cache).
Trusted trigger click starts the first-use clock; composed calendar focus event
ends focus latency. One subsequent RAF is separately reported; neither is INP or
confirmed paint. No intentional focus lead. Report observed preparation timestamps,
navigation-to-focus and actual completed encoded JS bytes at each snapshot.

Thirty successful samples per final promoted configuration. Serial seeded randomized
matched blocks under the shared browser lock. Qualification/profile samples excluded;
stop on failures or changed asset fingerprints, preserve attempts, no trimming or
zero-filling. Report medians/p75/spread and exploratory matched bootstrap intervals.
Report absolute and percentage changes with direction notes. Source/build/raw and
analysis receipts are frozen together; historical performance artifacts unchanged.

Retention is separate: five Chromium contexts per promoted arm, 100 mount/open/close/
settle/remove cycles, double-GC checkpoints0/10/50/100, detached node/listener/document
and heap counts. Modules/registry definitions remain resident. No leak-free claim.
Physical mobile and actual speech require manual review, separate from emulation.

Selection acceptance is measured from the field's `en-change` dispatch to its
completed update; it excludes the preceding trusted gesture and is not INP.
Long-task and layout-shift observations are recorded when supported; null means
unavailable. Retention checkpoints wait 300 ms before double GC to allow exit
motion/queued cleanup. Samples remain fresh browser processes and contexts.
The shared date feature caches only module promises/definitions, never registries
or DOM nodes; this avoids allocating the general registry loader for load-only work.
