# Component comparison: Spectrum 2 and Fluent 2

Audited 2026-09-20 as part of the Radix-inspired theme addition. This is a component and pattern comparison, separate from the existing theme fidelity and pressed-state reports. No component implementation is added by this audit.

## Scope and evidence

The local inventory contains **77 public custom elements**. Classification uses the public API inventory (`packages/elements/public-api.json`), Custom Elements Manifest (`packages/elements/custom-elements.json`), supported exports, implementation and component READMEs, rather than names in the Showcase alone. The inventory receipt (`artifacts/radix-refresh/component-audit-sf/local-inventory.json`) records source hashes and the inspected tags.

The Adobe baseline is the current **`@react-spectrum/s2`** catalogue linked by [React Spectrum's installation guide](https://react-spectrum.adobe.com/getting-started). [Spectrum Web Components](https://opensource.adobe.com/spectrum-web-components/) is a useful secondary comparison, but its catalogue and visual generation must not be silently substituted for React Spectrum 2. In particular, older Web Component-only entries are not evidence that the current S2 React library has an identically named component.

For Microsoft, [Fluent 2's Web overview](https://fluent2.microsoft.design/components/web/react) links **React v9** and **Web Components v3**. They have different inventories. This audit retrieved the [actual WC Storybook index](https://storybooks.fluentui.dev/web-components/index.json) and current official source at commit `babf26015958505fc6fc0216724f2f61244f829c`; the receipt (`artifacts/radix-refresh/component-audit-sf/fluent-source-manifest.json`) records URLs and hashes. The deployed Storybook's exact package version remains unestablished. Its “Split-Button” story is a composition of `fluent-menu split` and slotted actions: there is no separate `SplitButton` export in the inspected WC index. Tags, TagPicker, Card, AvatarGroup, Persona, List, Carousel and Toast from the React comparison are not present as equivalent exports in this WC snapshot. A Storybook title alone is not a count of custom elements.

**Classification:** “existing” means a supported local functional counterpart, not pixel or exhaustive behavioral parity; “partial” means an existing component lacks a relevant behavior or presentation; “recipe” means semantic HTML and existing elements should normally be composed; “missing primitive” means a reusable interaction/semantics contract is absent. Priority is a proposal for our library, not the external library's recommendation.

## Existing breadth that should not be reported as missing

| Area | Existing local counterpart | Comparison boundary |
| --- | --- | --- |
| Disclosure, navigation and actions | Accordion/items, tabs/panels, breadcrumbs, navigation/groups, links, buttons and toolbar | Covers the ordinary S2 and Fluent families. `en-toolbar` has roving navigation for direct buttons and normal Tab order for mixed controls; a toolbar is already shipped. Toggle, joined/split presentation and overflow are separate gaps below. |
| Form basics | Text field, textarea, search, native select/options, checkbox, radio/group, switch, number field | Common S2/Fluent controls already exist. The generic Field/Label wrappers in React do not each imply a missing element: our controls own same-shadow labels, descriptions and errors. |
| Dates, time and ranges | Date input, date picker, calendar and time field | Date picker/calendar already support range selection, unavailable-date callbacks and range Parts. Time entry already supports locale, 12/24-hour cycles and minute/second precision. Do not propose their basic existence again. |
| Floating surfaces | Dialog, drawer, popover, tooltip, menu/items and command palette | Menus already support nested menus, checkbox/radio commands, typeahead and touch replacement submenus. Tooltip already has delayed hover, keyboard focus, Escape and a pointer corridor. |
| Feedback and identity | Alert, toast/region, badge, avatar, presence/group, skeleton, spinner and progress bar | MessageBar/InlineAlert, Toast, Avatar/Persona and ordinary progress have counterparts. Our visible status labels are useful accessibility support. Some presentation and semantic variants remain partial. |
| Collections and media | Native table wrapper, data table, tree/items, carousel/slides and card | Data table has sorting, filtering, selection, pagination, virtualization and keyed reveal; tree has multiselection, lazy children, virtualization and reordering. These are not absent merely because their APIs differ from React. |
| Color, files and layout | Color picker/field/plane/slider/wheel, swatch, file upload, stack and split view/splitter | Color controls, resizable panes and native file selection/drop already exist. File upload supports external drop targets, rejection constraints and removal; transport stays application-owned. |

These findings come from the local implementation, particularly menu (`packages/elements/src/menu/README.md`), toolbar (`packages/elements/src/toolbar/element.ts`), form adapters (`packages/elements/src/forms-private/README.md`), date picker (`packages/elements/src/date-picker/element.ts`), data table (`packages/elements/src/data-table/element.ts`), tree (`packages/elements/src/tree/element.ts`), file upload (`packages/elements/src/file-upload/element.ts`) and the inventory receipt. They avoid conflating a component rename with a new capability.

## Gaps that matter for complete comparisons

| External pattern and evidence | Actual local boundary | Proposed delivery |
| --- | --- | --- |
| **Removable/interactive tags and tag groups.** S2 [TagGroup](https://react-spectrum.adobe.com/TagGroup) supports removal and link tags; Fluent has [Tag](https://fluent2.microsoft.design/components/web/react/core/tag/usage) and [TagPicker](https://fluent2.microsoft.design/components/web/react/core/tagpicker/usage). | **Missing primitive.** `en-badge` is intentionally noninteractive. `en-token-editor` is a multiline document editor with extension-owned atomic tokens; it is not a form-associated multivalue picker. | **P1:** a tag/group contract for remove intent, keyboard focus recovery, disabled items, accessible names and deletion announcements; then a tag picker with accepted key arrays, filtering, freeform policy, form/reset/validation and wrapping. Preserve app ownership of remote data. |
| **Multiple selection and rich options in dropdowns.** Fluent [Dropdown](https://fluent2.microsoft.design/components/web/react/core/dropdown/usage) explicitly supports multiselect and text alternatives for rich options. | **Partial.** `en-select` is native single-select; `en-combobox` is finite, editable, single-selection with plain-text results. A menu of checkbox commands is not automatically a form dropdown. | **P1:** decide between an accessible standalone listbox/picker primitive and extending the current combobox. Specify keys separately from query text, groups, descriptions, multiple values and touch/screen-reader navigation before adding visual slots. Keep the native select as a useful separate choice. |
| **Toggle actions.** S2 [ToggleButtonGroup](https://react-spectrum.adobe.com/ToggleButtonGroup) supports single/multiple selection; Fluent [buttons](https://fluent2.microsoft.design/components/web/react/core/button/usage) and current [WC ToggleButton](https://github.com/microsoft/fluentui/blob/babf26015958505fc6fc0216724f2f61244f829c/packages/web-components/src/toggle-button/toggle-button.ts) expose persistent pressed state. | **Partial/missing primitive.** `en-toolbar` exists; `en-segmented-control` is a radio choice, not a set of independent toggle actions. `en-button` forwards selected ARIA attributes but **does not forward `aria-pressed`** to its native button. Native styled `<button aria-pressed>` can be composed today. | **P1:** an explicit toggle contract on a button or dedicated toggle element, with `true`/`false` and deliberate mixed-state policy, then group ownership. Include selected paint distinct from transient `:active`. Test toolbar participation, controlled rollback, native semantics and disabled behavior. |
| **Selectable cards, selection tiles and card collections.** S2 [SelectBoxGroup](https://react-spectrum.adobe.com/SelectBoxGroup), [CardView](https://react-spectrum.adobe.com/CardView), and Fluent [Card](https://fluent2.microsoft.design/components/web/react/core/card/usage). | **Partial plus missing collection behavior.** `en-card` is a content surface without whole-card action, selection or focus management. Radio/checkbox labels can already make simple selection tiles. Data-table selection is not a visual card grid. | **P1:** first publish native radio/checkbox card recipes; add a selectable collection only when keyboard navigation, item actions and selection ownership are explicit. Support separate link/button/selection semantics. Never nest interactive controls inside a stretched button. Fluent's focus-trapping card modes are source options, not defaults to copy indiscriminately. |
| **Selectable/reorderable list collections.** S2 [ListView](https://react-spectrum.adobe.com/ListView) includes selection, item actions and optional drag/drop; Fluent [List](https://fluent2.microsoft.design/components/web/react/core/list/usage) distinguishes plain-list and selection roles. | **Missing generic collection primitive.** `en-activity-feed` retains authored content for a history; navigation owns links; tree owns hierarchy. None is a generic selectable list. Native `<ul>` already solves informational lists. | **P2:** a finite list collection sharing proven keyed selection/focus primitives, with explicit plain list versus selection/action semantics. Add reorder only with keyboard alternatives, announcement and focus recovery. Do not use `listbox` for arbitrary embedded interactive controls. |
| **Two-thumb ranges.** S2 [RangeSlider](https://react-spectrum.adobe.com/RangeSlider). | **Missing primitive.** `en-slider` has one numeric value and one native range control; two nearby sliders are not an equivalent interval contract. | **P1:** a two-endpoint range element or mode, with independent thumb names, ordered bounds, step/crossing policy, RTL, keyboard, form reset and accessible exact-value alternatives. Current single-value slider behavior should remain stable. |
| **Menu variants and grouped actions.** Fluent [Menu](https://fluent2.microsoft.design/components/web/react/core/menu/usage) has named grouping; [WC Menu](https://github.com/microsoft/fluentui/blob/babf26015958505fc6fc0216724f2f61244f829c/packages/web-components/src/menu/menu.ts) exposes context and split delivery. | **Partial.** Nested/checkable commands already work. Local items must remain direct menu children; named `role=group` wrappers are outside the keyboard ownership contract. No public pointer-position/context trigger lifecycle exists. | **P1/P2:** document split-button composition now; add a joined-action style recipe and targeted menu group/header support. Context menu needs coordinates, ContextMenu/Shift+F10 handling, dismissal and restoration to the original invoker, not just a right-click listener. Do not call all of this a missing Menu. |
| **Contextual help beside field labels.** S2 [ContextualHelp](https://react-spectrum.adobe.com/ContextualHelp) and Fluent [InfoLabel](https://fluent2.microsoft.design/components/web/react/core/infolabel/usage). | **Recipe plus field-composition gap.** Button + popover supplies the interaction, but our label slot requires noninteractive phrasing content. Putting an info button inside it violates that documented contract. | **P1:** a label-adjacent help-action slot or native-field composition recipe with explicit accessible relationships. Keep essential help in the persistent description. A new `en-info-label` is optional, not the prerequisite. |
| **Bulk action bar and overflow.** S2 [ActionBar](https://react-spectrum.adobe.com/ActionBar), plus action/button groups. | **Recipe/partial.** Table/tree selected keys and `en-toolbar` already supply the ingredients. No integrated selected-count/clear-selection/sticky bulk bar or automatic overflow policy is exposed. | **P2:** a documented app-owned selection-toolbar recipe, then shared overflow measurement/keyboard behavior if repeated use warrants it. Merely laying out buttons does not require another element. |
| **Meter and determinate circular progress.** S2 [Meter](https://react-spectrum.adobe.com/Meter) and [ProgressCircle](https://react-spectrum.adobe.com/ProgressCircle). | **Missing semantic/presentation variants.** `en-progress-bar` renders native task progress; `en-spinner` is indeterminate. Neither is a measurement meter, nor a determinate ring. | **P2:** native `<meter>` styling/recipe first; an element only if shared value formatting/thresholds warrant it. Add determinate circular progress as a progress presentation with equivalent accessible value and label. Do not relabel an indeterminate spinner as completed percentage. |
| **Avatar/persona variants and rating display.** Fluent [AvatarGroup](https://fluent2.microsoft.design/components/web/react/core/avatargroup/usage) has spread/stack/pie and popup overflow; current WC index has Rating Display. | **Partial/presentation.** Presence/group already handles identity, visible status and expandable overflow, but no avatar-only stack/pie or overflow popover. `en-rating` is editable integer radio selection, not a fractional summary. | **P2:** identity layout recipes plus an explicit status/glyph contract; a noninteractive rating display recipe with text such as “4.5 out of 5, 200 reviews.” Do not disable an editable form to simulate a read-only summary. |
| **International date/time depth.** S2 [DatePicker](https://react-spectrum.adobe.com/DatePicker) supports date/time values, additional calendar systems and multiple visible months. | **Partial.** Our date values remain ISO local dates; the calendar adapter permits Gregorian and modern Buddhist presentation, while time-field is wall time independent of timezone. Range selection already exists. | **P2:** a deliberate optional date/time/calendar adapter expansion with separate date, wall-time and zoned-instant types. Multi-month presentation and segmented date editing are independent proposals. Avoid suggesting that changing locale or theme colors implements calendar arithmetic/timezone semantics. |
| **General object drag/drop.** S2 [DropZone](https://react-spectrum.adobe.com/DropZone) accepts files and other data; its collection drag/drop handles reorder/insert. | **Partial.** FileUpload's controller deliberately accepts `Files`; it is already a file dropzone. Tree reorder exists. General text/object transfer between collections does not. | **P2:** extend reusable drag/drop primitives only with typed payloads, keyboard operations, rejection feedback and focus/announcement contracts. File transport, upload retries and persistence remain app services. |

## Catalogue items best handled as recipes or narrower extensions

**Native semantics and content.** Divider/separator, FieldLabel, HelpText, Text, Heading, LabeledValue, Image/Asset/Thumbnail, Form, CheckboxGroup and IllustratedMessage map naturally to `<hr>`, `<label>`, descriptive content, headings, `<dl>`, `<img>`, `<form>`, `<fieldset>/<legend>` and a composed empty-state region. Publish consistent styles and examples before adding wrappers. Images still require application-owned alternative text; assets and illustrations are content, not a reason to add a component per image category. Our small built-in icon set is not the equivalent of either library's complete asset ecosystem; adapter/documentation work is more useful than bundling all their branded assets.

**Action presentation.** ActionButton, LinkButton, ButtonGroup, CompoundButton, MenuButton and SplitButton mostly share existing button/link/menu behavior. Compound title/description layout and joined boundaries deserve recipes or slots. Native anchors must retain navigation semantics when styled as buttons. A native submit/reset button recipe remains necessary because our `en-button` intentionally renders `type="button"` and delegates form submission to its consumer. This is a documented behavioral boundary, not a theme-color issue.

**Other partial variants.** A swatch palette needs single/multiple choice semantics beyond `en-swatch` activation; compose labeled radio/checkbox controls first. Tabs overflow needs a focused-item reveal/overflow policy, not a second Tabs implementation. AlertDialog needs an explicit inner semantic role/description and initial-focus contract beyond a confirmation layout inside the existing native modal; changing the outer custom-element's role is not sufficient. Drawer currently supplies a modal edge panel; [Fluent's inline/nonmodal drawer](https://fluent2.microsoft.design/components/web/react/core/drawer/usage) is an additional interaction/layout mode. Teaching/coachmark tours, profile cards and larger empty states should begin as application compositions with popover/card/steps and ordinary headings, with tour progression and persistence owned by the application.

These are **comparison proposals**, not claims that every item appears in both React catalogues. Coachmark/Coach Indicator and Tabs Overflow, for example, are visible in the secondary Spectrum Web Components catalogue. Confirm the selected source flavor before treating them as exact S2 React parity work.

## What this means for the theme API

The highest-value additions are missing **semantic state and anatomy**, not more global color tokens. Themes cannot manufacture a selected card, a second slider thumb, removable-tag focus recovery or a multivalue form model. Each new primitive should declare its persistent and transient states, stable Parts, density geometry, complete focus treatment and portable token hooks together. Button toggle selection and pressed feedback must remain separate; label help must preserve cross-shadow naming; list options must distinguish selected value from keyboard candidate.

Before expanding the catalogue broadly, build one comparison fixture per proposed shared family using native HTML and existing components. Promote it to an element when repeated behavior, form participation or keyboard ownership justifies the contract. Validate light/dark, RTL, 200% text, coarse pointer, reduced motion, forced colors, SSR/hydration and cancellation only for the new behavior being shipped. This audit is a source/capability review; it does not claim a fresh full accessibility certification or runtime parity test of either external library.
