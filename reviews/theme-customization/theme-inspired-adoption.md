# Theme API adoption across the nine presets

This is the implementation follow-up to the [API recommendations](theme-api-implementation.md). All six inspired themes and all three original themes now deliberately configure the applicable new roles, with separate light/dark baselines and shipped variant companions. The earlier research reports remain source observations at their original checkpoints; their statements that tracking, card elevation, pressed motion or family timing are unavailable are superseded here.

## Original themes

The three originals use the same delivery and APIs, with no separate application template.

| Theme | New expression |
| --- | --- |
| **Vellum** | Italic small and large editorial headings, tighter medium headings and spaced metadata; fine 2px field corners separate from action geometry; 18px choices and a compact 32×18 switch. Cards have two fine, displaced paper-edge shadows. Outlined secondary actions look like paper labels; primary presses move the entire button half a pixel and lose their small resting shadow. Navigation uses a thin marginal marker and tabs use an ink underline. Popups are quicker than the more leisurely dialog and toast. |
| **Signal** | Spaced monospaced metadata and strong labels, tighter display text, square 2px fields with a 3px invalid contour, 22px choices and a broad 48×24 switch. Secondary buttons invert ink/paper, then switch to fluorescent yellow with explicitly dark text. Primary/secondary button shadows collapse from 3px to 1px while the whole button moves 2px. Yellow selected navigation/tabs have independently paired dark ink. Dialogs appear immediately; popup and toast timing stays short and linear. The existing hard card shadow remains. |
| **Kinetic** | Tightly set oversized headings, rounded 16px fields distinct from pill actions and 32px cards; 24px choices and a 52×30 switch. Mint secondary actions complement violet primaries. Layered colored card and button elevation, .94 whole-button compression and a shallower held shadow make buttons tactile. Selected tabs/navigation use violet with paired cream ink. Popups respond in 160ms; dialogs use 360ms and toast 300ms, preserving their different visual roles. |

Reduced motion removes press movement and visual transition delays. Pressed color/elevation still supplies feedback. Disabled guards remain component-owned; popup movement is a theme choice. Shadcn suppresses it, matching Rhea, while Astryx retains it. The themes do not change focus movement, event ordering, selection, dismissal or layout allocation. The transformed control’s painted and hit rectangles follow its motion.

## Delivery and trust

- Canonical definitions carry a typed `companion` recipe beside each light/dark baseline. All nine recipes map primary, secondary, ghost and danger independently. The three originals suppress decorative button shadows on ghost and danger actions.
- The document presentation controller compiles and installs the trusted companion after token CSS, owns/restores the theme boundary, and regenerates after editing. Both explicit and automatic appearance work. Nested full-theme boundaries are excluded.
- Showcase **Download CSS** returns the complete paired token CSS plus the companion. Apply the named `data-en-theme` boundary and `data-en-appearance="auto"`, `"light"` or `"dark"`. Fonts remain separate assets.
- JSON keeps the standard v2 token-pair envelope unchanged and adds a separately identified companion to the outer, build-bound review bundle. Reopening regenerates the companion from the authoritative catalogue and current tokens; modified CSS, recipes or identities are rejected even when the envelope checksum is recomputed. Imported CSS is never installed.
- The maintainer generator writes the standard paired CSS plus a separately hashed `.companion.css` sidecar. Load that sidecar after the token CSS. Both are recorded in the preparation manifest.
- Consumed-role provenance covers all six external/product inspirations. The source manifest stores URL/digest identities; available local raw captures are hash-checked. Holotable explicitly hashes recorded observations, not unavailable upstream bytes. Original themes are authored design decisions, not external measurements.

Companion selectors reach public light-DOM custom-element hosts and native class recipes. They cannot traverse another component's private shadow tree. The element's inherited semantic tokens still apply there; a component-specific Part or additional internal variant consumer would be needed for complete internal-button equivalence. Root boundaries are containers: put themed controls beneath the named boundary.

## Remaining API limits

This pass deliberately uses the current API. It does not add a new token type or expand companion target syntax. Further worthwhile work remains: switch checked-thumb dimensions/paint, field and button state-specific inset shadows, separate field edges, optional surface blur/gradients, dynamic size-dependent press formulas, family title/label typography, tab active tracking and source-specific variant vocabularies. Code font tracking is not currently a connected role. Whole-button pressing is now supported; the correction and popup exception are documented in [the follow-up](theme-press-correction.md).

For these remaining gaps, the [five-library component comparison](theme-refresh-library-comparison.md) and [authoring contract](theme-api-authoring-contract.md) distinguish missing component behavior from visual theme capability. Font licensing, physical-device touch and assistive-technology acceptance remain separate from automated theme verification.

## Verification

The catalogue suite checks all eighteen branches, managed editing/undo, byte-identical paired reopen, companion regeneration and tamper rejection. The focused adoption browser suite checks all nine themes in Chromium, Firefox and WebKit: actual custom/native variant paints, stable layout frames and whole-button motion, field corners, card shadow, selected tabs, nested-scope isolation, automatic appearance, reduced-motion press behavior, standalone exported CSS and state retention when switching/resetting. The retained theme-refresh corpus supplies JSON reopening, fonts, narrow RTL/200% text, reduced-motion and supported forced-colors checks. Detailed results and the publication receipt are recorded in `artifacts/theme-adoption/verification.json`; this section describes the test scope, not user acceptance.
